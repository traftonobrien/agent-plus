# Agent+ Project Instructions

## Purpose

Use this repository to document a controlled AI-assisted baseball research workflow. It is a public example package, not a data or modeling repository.

`AI_WORKFLOW.md`, `AI_AGENT_OUTPUT_POLICY.md`, and `ESSENTIAL_WORK_PROTOCOL.md` are binding alongside this file.

## Stable rules

1. Start with a research contract before substantive analysis.
2. Use deterministic checks for counts, schemas, hashes, tests, and official metrics.
3. Give each model a bounded task, permitted inputs, stop condition, and acceptance check.
4. Keep maker, evaluator, verifier, and human decision roles separate.
5. Treat `PASS`, null result, and `BLOCK` as valid outcomes.
6. Never claim prediction, decision value, or operational impact without the matching evidence level.
7. Start with `scripts/ai-context.sh` and the exact planning artifact named by hot memory.
8. Use `.planning/STATE.md` to identify the active public phase. Do not skip dependencies.
9. When the owner explicitly requests delegation or parallel work, Sol may directly create bounded,
   model-selected Luna sub-agents under `AI_WORKFLOW.md`; do not require manual cross-chat handoffs.
10. Engineering readiness reviews collect the complete reachable defect class before one bundled
    repair. A second BLOCK at the same interface forces simplification, not a third local patch.
11. Validate engineering and scientific/live task packets with `scripts/anti_loop_guard.py` and the
    `.agent-plus/engineering-boundaries.json` ledger before promotion.
12. Select one bounded session mode (`quick`, `standard`, `deep`, or `scientific/live`) and apply its
    model, worker, context, time, and authorization limits. Extra capacity never grants authority,
    retries, context, reviewers, or promotion rights.
13. Keep successful recovery interfaces closed. Unattended execution uses one authorized launch,
    process-written durable evidence, zero AI polling, and one result check on return.

## Public safety

Do not add raw baseball data, credentials, private paths, personal transcripts, proprietary artifacts, or unlicensed third-party material. Use sanitized examples. Label examples and placeholders clearly.

## Context layers

- `AGENTS.md` defines project-wide instructions.
- `CLAUDE.md` defines the Claude runtime profile.
- `.claude-memory.md` records changing, verified project state.
- An Obsidian Brain stores curated long-term knowledge.
- A handoff records one bounded task's restart state.

## Output

Apply `AI_AGENT_OUTPUT_POLICY.md` automatically. Use basic everyday English first for state,
progress, blocker, and current-work updates. Keep exact technical records in a final
`Technical details` section only when they are needed or requested.

## Canonical system ownership

- This repository is the canonical public Agent+ distribution.
- Consumer and proving projects may adapt Agent+ to local scientific needs. They do not become the
  source of truth for generic Agent+ controls.
- Port reusable improvements into this repository with sanitized examples and synthetic tests.
  Never copy project data, private state, receipts, paths, or transcripts upstream.
- Publish an accepted Agent+ version before a consumer project declares the reusable control
  synchronized.
- Use `.agent-plus/local-projects.json` only as an ignored local registry. It can expose a bounded
  project context to an Agent Plus Brain task without merging project memory or authority.

## Closeout

Update verified state only after proportionate checks. Record one next action, open limits, and an exact restart command. Do not use a chat transcript as the source of truth.
