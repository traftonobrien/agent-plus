# Source Log Workflow

## Trigger

Use when a research contract needs source discovery, source admission, or claim-to-source traceability.

## Purpose

Create a source log that distinguishes discovered material from admitted evidence.

## Required inputs

- Contract question and claim boundary.
- Candidate source citation or stable URL.
- Source type and provenance requirements.

## Allowed actions

- Record candidate sources.
- Check author, date, scope, and claim relevance.
- Mark a source admitted, pending, or rejected.

## Required outputs

- Updated source log using the template.
- Admission decision and concise rationale.
- Unresolved provenance or scope gaps.

## Acceptance checks

- Each admitted source supports a named claim or method.
- A source type is recorded.
- Discovery is not mislabeled as validation.

## Handoff requirements

State admitted source IDs, pending sources, and the next contract or evidence action.

## Explicit limits

Do not make a result claim from a source log. Do not collect personal data or private sources without authorization. Do not treat a summary as the original source.
