# Agent+ 0.4.3

This compatible patch preserves request meaning and constrains package checks to shipped public inputs.

## Changes

- The existing task card records the actual question/population, output mode/exclusions, consequential unresolved scope, semantic contract, known-answer cases and reconstruction ownership.
- The existing protocol connects these fields to request fidelity and analytical meaning. It requires relevant tiny scalar/vector/grouped/missing-value and signed-endpoint cases before expensive execution.
- Historical reconstruction stays separate when it is not a dependency of the normal run. Accepted contracts and project adapters retain their definitions.
- Canonical and bootstrap owners match. A real installation test checks delivery for research and product profiles.
- Existing package whitespace/link checks use the same Git publication inventory as public safety. Ignored evidence is excluded. Tracked ignored paths and nonignored public additions remain covered.
- Public local links must resolve to published files or directories with published descendants. Seven synthetic cases execute the actual validator block and preserve negative checks.

## Compatibility and limits

No new CLI option, dependency, schema, managed set, bootstrap interface or validator framework is introduced. Canonical CI and detached verification use the existing validator command.
Guidance is instruction, not technical enforcement of model behavior. Semantic/helper cases do not prove analytical runtime correctness.
The change does not authorize data access, scientific claims, publication or automatic consumer upgrades. Model compliance, workflow effectiveness and scientific readiness remain unmeasured or separately gated.
See [control guarantees](../control-guarantees.md) for the existing system boundaries.
